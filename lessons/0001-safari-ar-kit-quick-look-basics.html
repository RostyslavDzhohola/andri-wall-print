Lesson 0001

Safari does not run your web app's ARKit session. It hands the model to AR Quick Look.

Your first tangible win: after this lesson, you should be able to point at the Preview Picture code and explain what happens when a customer taps Place on wall on iPhone Safari.

The mental model

Web page React renders the preview page, poster image, and AR launch button.
Asset bundle The project provides poster, GLB, and USDZ files with real print dimensions.
Safari trigger The button is an <a rel="ar"> link to the USDZ file.
Native viewer Apple AR Quick Look opens and uses ARKit underneath for surfaces and tracking.

What this project already does

The handoff code

components/ar/native-ar-launcher.tsx renders the Quick Look link, checks whether the user is on iPhone Safari, and blocks known bad browser paths before launch.

The fixed-size rule

lib/ar-launcher.ts adds #allowsContentScaling=0 to the USDZ URL so the wall print should stay at its authored physical size.

The model files

lib/ar-asset-generator.ts creates the poster, GLB, and USDZ from artwork and dimensions. Safari needs the USDZ. Web/Android paths also use GLB.

The delivery headers

next.config.ts serves checked-in .usdz assets as model/vnd.usdz+zip, which WebKit says Safari expects for USDZ recognition.

The useful basics

For the current web product, learn AR Quick Look before deep native ARKit. AR Quick Look is the product surface. ARKit is the underlying native system that makes the viewer understand motion, walls, floors, and anchors.

  • ARKit: native Apple AR framework. It handles tracking, surfaces, anchors, and scene understanding.
  • AR Quick Look: Apple's system viewer that Safari can open from a USDZ link.
  • USDZ: the iOS/Safari AR file. If this is missing, wrong-sized, too large, or served with the wrong type, the customer path breaks.
  • rel="ar": the Safari hint that a link is an AR launch, not just a normal download/navigation.
  • allowsContentScaling=0: the Quick Look setting that disables user resizing, important for true-size wall art.

Should you learn native iOS ARKit too?

Yes, learn the basics

It will help you reason about what Quick Look is doing: world tracking, plane detection, anchors, real-world scale, and why walls can be hard to detect in bad lighting or on blank surfaces.

But do not switch yet

A native app is helpful when you need custom camera UI, measurement, persistent saved wall placements, richer editing, or interactions that Quick Look cannot expose. It is not required for a shareable Safari sales preview.
