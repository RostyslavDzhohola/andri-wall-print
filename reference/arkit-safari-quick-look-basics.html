Safari ARKit Quick Reference

For Preview Picture, Safari does not give the webpage a live ARKit session. The webpage prepares and links the right assets, then Safari hands the USDZ file to Apple's native AR Quick Look viewer.

1. Preview page Customer opens /preview/[slug].
2. Web assets Page has poster, GLB, and USDZ URLs.
3. Safari link rel="ar" link points to USDZ.
4. Quick Look Native viewer opens outside the DOM.
5. ARKit work Device tracks motion and detects surfaces.

Terms

ARKit

Apple's native framework for world tracking, scene understanding, plane detection, anchors, and sensor-backed AR data.

AR Quick Look

Apple's built-in viewer for opening USDZ or Reality files from Safari, Messages, Mail, apps, and more.

USDZ

The iPhone Safari asset that Quick Look opens. In this project it represents the wall print as a real-size flat plane.

GLB

The web-friendly 3D asset used by model-viewer and Android Scene Viewer. It is not the primary Safari Quick Look file.

Browser vs Native iOS

Question Safari Quick Look path Native iOS ARKit path
Can the user open it from a shared link? Yes. This is the current product advantage. No. They must install/open an app.
Can the web page control the live camera AR session? No. Quick Look is a native viewer outside the webpage DOM. Yes. The app can own ARKit/RealityKit rendering and interaction.
Can we show custom React UI over AR? Not inside Quick Look. Use Quick Look banners or return-to-page actions for limited flows. Yes. Native UI can be layered around the AR view.
Can we keep the wall print true-size? Yes, through correct model dimensions and Quick Look scaling settings. Yes, with direct control over model transforms and anchors.
Best learning focus right now? USDZ, MIME type, rel="ar", asset dimensions, Safari/iPhone testing. World tracking, plane detection, anchors, RealityKit entities, permissions.

Rules of Thumb

Learn native ARKit basics for mental models, not because the current web MVP needs a native app.

Native ARKit becomes worth serious time when you need custom camera UI, wall measurement, persistence across rooms, richer editing, or interaction that Quick Look cannot express.
